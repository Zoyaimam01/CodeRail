ROADMAP:

Here is a structured practice roadmap for mastering entry-level Dynamic Programming (DP) and precomputation patterns using the provided problem set.

---

### 1. Core Concepts to Learn

Before diving into these problems, make sure you understand these foundational concepts:

*   **State & Transition:** Defining what `dp[i]` represents mathematically and determining how to calculate `dp[i]` using previously computed states (e.g., `dp[i - 1]`).
*   **Space Optimization (Rolling Variables):** Realizing when `dp[i]` only depends on `dp[i - 1]` so you can optimize memory from $O(N)$ space to $O(1)$ space using a few variables.
*   **Prefix and Suffix Precomputation:** Pre-calculating properties (like sums, minimums, or maximums) from left-to-right and right-to-left to answer queries or exclude specific elements in $O(1)$ time.
*   **Prefix Sums on Precomputed States:** Combining mathematical counting with precomputed DP values to answer range queries $[l, r]$ quickly.

---

### 2. Recommended Solving Order & Why

#### **Step 1: [900] 580A - Kefa and First Steps**
*   **Focus:** Classic 1D Subarray DP / Linear Scan
*   **Why start here?** This is the pure entry point into DP. It teaches you how to maintain a state based *only* on the previous element (`dp[i]` depends on `dp[i-1]`). 
*   **Key Concept:** `dp[i]` = length of the longest non-decreasing subarray ending at index `i`.
    $$\text{dp}[i] = \begin{cases} \text{dp}[i-1] + 1 & \text{if } a[i] \ge a[i-1] \\ 1 & \text{otherwise} \end{cases}$$

---

#### **Step 2: [1100] 1971D - Binary Cut**
*   **Focus:** Transition Logic & Greedy Optimization
*   **Why next?** It builds on consecutive element checks. Instead of contiguous numbers, you look at adjacent character transitions in a string (`"01"` vs `"10"`).
*   **Key Concept:** Counting continuous blocks of identical characters and analyzing transitions. Recognizing that at most one `"01"` block can be kept contiguous without splitting.

---

#### **Step 3: [1100] 522B - Photo to Remember**
*   **Focus:** Prefix & Suffix Precomputation (The "Exclude One" Pattern)
*   **Why next?** This transitions from simple linear DP to array precomputation techniques. To solve the problem for every person $i$ without recalculating in $O(N)$ each time, you precalculate properties to answer in $O(1)$.
*   **Key Concept:** To find the maximum height excluding person $i$, precompute `prefix_max[i]` (max height from index $0$ to $i-1$) and `suffix_max[i]` (max height from index $i+1$ to $N-1$). The max height excluding $i$ is $\max(\text{prefix\_max}[i-1], \text{suffix\_max}[i+1])$.

---

#### **Step 4: [1200] 1485B - Replace and Keep Sorted**
*   **Focus:** DP / Precomputed Contribution + Prefix Sums
*   **Why last?** This combines independent local element states with Range Queries. You must precompute the number of choices for each element in the array and use a prefix sum array to process $Q$ independent queries in $O(1)$ time each.
*   **Key Concept:** For an element $a[i]$, it can take values strictly between $a[i-1]$ and $a[i+1]$. The total ways for element $i$ is $(a[i+1] - a[i-1] - 2)$. Boundary conditions at $l$ and $r$ must be handled separately.

---

### 3. Common Patterns

1. **Consecutive State Dependence (1D DP):**
   * *Used in:* 580A, 1971D
   * *Pattern:* Inspecting $a[i]$ relative to $a[i-1]$ to reset or extend a running counter.

2. **Prefix and Suffix Sweep ("Exclude $i$" Pattern):**
   * *Used in:* 522B
   * *Pattern:* Whenever a problem asks: *"Find the result for the entire array if element $i$ is removed,"* think of precomputing `prefix[i-1]` and `suffix[i+1]`.

3. **Contribution + Prefix Sum Range Queries:**
   * *Used in:* 1485B
   * *Pattern:* Precompute individual element contributions into an array `C[i]`, then build `pref[i] = pref[i-1] + C[i]` to evaluate any subarray range $[l, r]$ in $O(1)$.

---

### 4. Common Mistakes to Avoid

* **Confusing Subarray with Subsequence (e.g., 580A):**
  * *Subarray* elements must be contiguous in the original array.
  * *Subsequence* elements do not need to be contiguous (which would require $O(N \log N)$ LIS logic instead of $O(N)$ DP).

* **Boundary / Edge Conditions in Range Queries (e.g., 1485B):**
  * The endpoints $l$ and $r$ of a query $[l, r]$ usually have different choice bounds than the middle elements $l+1 \dots r-1$. Do not apply the general middle transition formula to the boundary elements $a[l]$ and $a[r]$.

* **Off-by-One Errors in Prefix/Suffix Arrays (e.g., 522B):**
  * Be extremely careful with 0-indexed vs 1-indexed arrays when reading `prefix_max[i-1]` or `suffix_max[i+1]`, especially when $i = 0$ or $i = N - 1$.

* **Using 2D/1D DP Arrays when $O(1)$ space is sufficient:**
  * For problems like 580A, keeping an entire `dp` array is okay, but recognizing that you only need `current_len` and `max_len` reduces memory usage and simplifies implementation.
